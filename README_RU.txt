GDS Viewer — Iteration 2 / первая версия нового кода / 01.11.2026

СОСТОЯНИЕ: ДАННЫЕ В S3 ПРОВЕРЕНЫ, КОД ПОДГОТОВЛЕН ДЛЯ GITHUB

Эта ветка содержит новый код Dash/Plotly и проверку подключения. Данные повторно
не включены: используется созданный ранее новый S3 bucket. Сам пакет ничего не
записывает в S3, не меняет IAM и не развёртывает приложение на Heroku.

1. Загрузите GDS_Viewer_Iteration_2.zip через CloudShell → Actions → Upload file.
2. Выполните:

   unzip -q GDS_Viewer_Iteration_2.zip
   cd GDS_Viewer_Iteration_2
   bash check_s3.sh --all

Имя bucket больше не вычисляется по региону CloudShell. Сначала читается
GDS_CloudShell_Kit/state/connection.json из соседней папки или домашней директории.
Если настройки не найдены, выполняется поиск существующего bucket с префиксом
gds-viewer-data-. Автовыбор выполняется только при единственном совпадении.
Регион определяется по настройкам создания или ответу AWS HeadBucket.
Для явно заданного bucket:

   GDS_S3_BUCKET=ваше-имя-бакета bash check_s3.sh --all

Проверка использует текущую AWS-сессию CloudShell. Ключи вводить не нужно.
Она читает current.json, сверяет SHA256 manifest.json, метаданные и все Parquet.
Ожидаемый итог для принятого набора:

   "status": "OK"
   "release": "v001"
   "records": 164
   "plot_curves": 265
   "parquet_checked": 164
   "samples_checked": 921550

Если current.json не найден, набор ещё не активирован: нужно завершить
04_activate_release.sh из предыдущего GDS_CloudShell_Kit. Если AccessDenied,
нужно разрешение GetObject для current.json и releases/* нового bucket.
При чтении сохранённых настроек достаточно доступа GetObject к данным.
Для автоматического поиска без настроек нужен s3:ListAllMyBuckets. Это право
используется только проверкой в CloudShell; приложению Heroku оно не требуется.
Путь к настройкам можно задать через GDS_STORAGE_CONFIG.
Политика чтения для Heroku создана предыдущим комплектом
в state/heroku_read_policy.json.

ЧТО РЕАЛИЗОВАНО

Wells: карта с красными точками, выбор кликом и прямоугольником, список скважин,
сброс выбора, фильтры возраста и типа кривой, поиск по скважине/публикации.
Идентификация по record_id: одинаковые названия и координаты не объединяются.
Совпадающие точки можно выбирать независимо через список Selected wells.
Фильтры карты не удаляют уже выбранные скважины из списка.

Таблица выбранных скважин: доступные кривые, исходные единицы, интервалы LAS,
метры/условная глубина, возраст, публикация, примечания и координаты.
Выбор нескольких строк, сортировка и фильтрация сохраняют связь по log_id.

Logs: кнопка Build logs, ограничение глубины, линейная/логарифмическая ось,
обратное направление оси X, отдельные дорожки и карта выбранных скважин.
Все выбранные кривые разбиваются на группы по 6 дорожек для читаемости.
Шкалы глубины независимы; условная глубина не выдаётся за истинную глубину скважины.
Пропуски образуют разрывы. Усреднения и уменьшения числа точек нет.
Положения по глубине, значения и единицы берутся из подготовленных LAS/Parquet.
Автоматическая логарифмическая ось — PERM, RESD, RESS, RES, SFLU.
Автоматическая обратная ось — NPHI, PHI, DT, SONIC. Режим можно изменить.
Старые фиксированные пределы X не перенесены: пределы определяются по данным.
На логарифмической оси значения ≤0 не отображаются; линейная ось их сохраняет.
После изменения выбранных скважин/кривых старый график очищается. После изменения
глубины/масштаба нужно снова нажать Build logs.

Ссылки LAS формируются один раз на запись. При нажатии приложение выдаёт свежую
временную S3-ссылку на 5 минут, не скачивая LAS на сервер заранее.

Стратиграфия: пустой индекс v001 корректно обрабатывается. Если в будущем появятся
совместимые интервалы, код отображает подписанные полосы формаций/периодов.
Отдельные колонки стратиграфии и внешний вид карты предстоит проверить на тестовом
Heroku. В этом наборе самих интервалов стратиграфии нет.

МОДЕЛЬ ЧТЕНИЯ

Вкладка браузера получает release_id + SHA256 manifest, а не числовые массивы.
Внутри одной вкладки версия фиксируется. Новая загрузка страницы читает current.json
заново и получает активную версию; текущие графики не смешивают разные выпуски.
Сервер проверяет хеши файлов и кеширует не более 24 таблиц Parquet на процесс.
Нет загрузки всех кривых при каждом клике; загружается файл конкретной скважины.
LAS не являются источником списков доступных каналов: правило available_for_plot
из согласованного каталога сохранено. 265 кривых доступны в 123 записях; остальные
41 запись остаются на карте и доступны для скачивания LAS.

ЛОКАЛЬНЫЙ ЗАПУСК С УЖЕ СКАЧАННЫМ НАБОРОМ

Python 3.12 рекомендован; для Heroku указан 3.12 в .python-version.
CloudShell с Python 3.13 также поддерживается: NumPy обновлён до 2.1.3.
check_s3.sh устанавливает только готовые бинарные пакеты, без сборки компилятором.
На компьютере с Python:

   python -m venv .venv
   # Linux/macOS: source .venv/bin/activate
   # Windows PowerShell: .venv\Scripts\Activate.ps1
   python -m pip install -r requirements.txt

Linux/macOS:
   export GDS_LOCAL_ROOT=/полный/путь/GDS_CloudShell_Kit/payload
   python app.py

Windows PowerShell:
   $env:GDS_LOCAL_ROOT="C:\полный\путь\GDS_CloudShell_Kit\payload"
   python app.py

Откройте http://127.0.0.1:8050. В этом режиме используется та же структура файлов,
что и в S3, без AWS-ключей. .env.example — пример переменных; автоматическое чтение
.env не включено.

ТЕСТОВЫЙ HEROKU — ПОСЛЕ ПРОВЕРКИ S3

Procfile готов для Gunicorn. Корень пакета должен стать корнем новой кодовой ветки.
Требуются Config Vars:
  GDS_S3_BUCKET — имя НОВОГО bucket;
  AWS_REGION — фактический регион bucket из результата check_s3.sh;
  учётные данные AWS только на чтение через стандартную цепочку boto3.

Для Heroku учётные данные CloudShell не переносятся автоматически. Их нужно
настроить отдельно в Config Vars через AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY
(и AWS_SESSION_TOKEN, если используются временные credentials) либо настроенную
федерацию. Секреты не помещаются в GitHub или в этот архив.

Развёртывание в этом шаге не выполнено. Доступ к веб-приложению наследует настройки
Heroku; приватность S3 сама по себе не ограничивает доступ к страницам приложения.
Карта использует внешний картографический фон CARTO, для него нужен интернет.
Старый исходник использовал спутниковую подложку Mapbox; здесь применяется
MapLibre без Mapbox token. Детали оформления уточняются при просмотре прототипа.

После запуска /healthz показывает работоспособность сервера; /readyz проверяет
доступ к активной версии и метаданным. Проверка всех измерений — check_s3.sh --all.

ИСПРАВЛЕНИЕ PYTHON 3.13 (редакция 2)

В исходном пакете NumPy 2.0.2 не имел подходящего wheel для Python 3.13,
поэтому pip переходил к сборке из исходников. В этой редакции закреплён
NumPy 2.1.3, а --only-binary=:all: запрещает такую сборку.
Если ZIP уже распакован, можно исправить его без повторной загрузки:

   sed -i "s/^numpy==2.0.2$/numpy==2.1.3/" requirements.txt
   sed -i "s/--no-cache-dir -r/--no-cache-dir --only-binary=:all: -r/" check_s3.sh
   bash check_s3.sh --all

https://numpy.org/doc/stable/release/2.1.3-notes.html

ИСПРАВЛЕНИЕ ОПРЕДЕЛЕНИЯ BUCKET (редакция 3)

Команда с AWS_REGION=us-east-2 больше не порождает имя несуществующего bucket.
Приоритет: явный GDS_S3_BUCKET → файл connection.json → один найденный GDS bucket.
Если bucket несколько, скрипт печатает варианты и просит указать GDS_S3_BUCKET.
Никакие бакеты и объекты не создаются и не переносятся.
Для обновления уже распакованного кода после загрузки новой версии ZIP:

   cd ~
   unzip -oq GDS_Viewer_Iteration_2.zip
   cd GDS_Viewer_Iteration_2
   bash check_s3.sh --all

https://docs.aws.amazon.com/cli/latest/reference/s3api/list-buckets.html
https://docs.aws.amazon.com/cli/latest/reference/s3api/get-bucket-location.html
