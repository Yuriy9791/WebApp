# GDS Viewer — Iteration 2

Новый код приложения Dash/Plotly для просмотра скважин и каротажных кривых из
подготовленного хранилища Amazon S3. Ветка: `gds-viewer-iteration-2`.

## Текущее состояние

- Подготовлен выпуск `v002`: 15 типов из полного старого CSV, 332 кривые
  вместо 265. Отбор выполняется глобально по типам и наличию значений в LAS.
  `Kurdistan-1` содержит доступные `GR` и `DT`. Для включения выпуска сначала
  обновите Heroku, затем загрузите и активируйте данные по
  [инструкции v002](docs/curve_catalog_v002_RU.txt).
- Загрузчик CloudShell использует только boto3 во временном окружении `/tmp`,
  без кеша pip и без библиотек интерфейса/аналитики. Готовые файлы проверяются
  по SHA256, затем загружаются через `tools/apply_cloudshell.sh`.
- Пользователь проверил живое хранилище из AWS CloudShell: `status: OK`, выпуск
  `v001`, 164 Parquet-файла, 265 доступных кривых, 921550 строк измерений.
- Подтверждённый регион хранилища — `eu-north-1`.
- 17 автоматических тестов прошли с принятым набором данных.
- Развёртывание на Heroku и визуальная проверка интерфейса в браузере ещё не выполнены.

## Возможности

- Карта, выбор скважин кликом и прямоугольником, фильтры возраста и типа кривой.
- Таблица кривых из LAS по всем типам старого CSV, с единицами, глубиной,
  публикациями и примечаниями; тип разрешён для всех скважин.
- Несколько каротажных дорожек, глубина вниз, выбор масштаба и диапазона.
- Скачивание исходных LAS через временные ссылки S3.
- Чтение активного выпуска через `current.json`, проверка SHA256 и ограниченный кеш.

## Проверка S3 в CloudShell

В каталоге приложения:

```bash
bash check_s3.sh --all
```

Скрипт использует сохранённый `GDS_CloudShell_Kit/state/connection.json`, а при
его отсутствии ищет единственный существующий бакет с префиксом
`gds-viewer-data-`. При нескольких совпадениях укажите имя явно:

```bash
GDS_S3_BUCKET=YOUR_BUCKET_NAME bash check_s3.sh --all
```

Скрипт устанавливает бинарные зависимости, включая `numpy==2.1.3`, и читает
данные. Имя бакета больше не строится из региона оболочки.

## Запуск приложения

Виртуальное окружение `.venv` создаётся скриптом проверки. Для запуска с S3
задайте имя бакета и его фактический регион; учётные данные берутся из стандартной
цепочки boto3. Проверка CloudShell не сохраняет переменные в родительской оболочке.

```bash
export GDS_S3_BUCKET=YOUR_BUCKET_NAME
export AWS_REGION=eu-north-1
.venv/bin/python app.py
```

Для запуска на своём компьютере с подготовленными локальными файлами используйте
`GDS_LOCAL_ROOT`, как описано в [README_RU.txt](README_RU.txt). `.env.example`
служит примером: приложение не загружает `.env` автоматически.

Точка входа — `app.py`, WSGI-объект — `app:server`. `Procfile` подготовлен для
Gunicorn, `.python-version` задаёт Python 3.12 для Heroku. Старые `App.py` и
`runtime.txt` доступны в истории и других ветках.

## Проверки

```bash
.venv/bin/python -m pip install pytest==8.4.2 'moto[s3]==5.2.5'
GDS_TEST_ROOT=/absolute/path/GDS_CloudShell_Kit/payload .venv/bin/python -m pytest -q
```

Для проверки расширенного выпуска дополнительно задайте
`GDS_EXPANDED_TEST_ROOT=/absolute/path/payload_v002`. Сборка воспроизводится
через `tools/build_release.py --archive ... --type-catalog ... --release v002
--batch batch-002 --output ...`; зависимости — `requirements-build.txt`.
Новый код читает оба выпуска, `v001` и `v002`.

Данные не включены в репозиторий. Без `GDS_TEST_ROOT` или набора в соседнем
каталоге 10 тестов с данными пропускаются; 7 тестов определения хранилища
работают без пользовательских данных. Подробности — в [TEST_REPORT.txt](TEST_REPORT.txt).

Проверки сервера: `/healthz` и `/readyz`. Полная проверка Parquet выполняется
отдельной командой `check_s3.sh --all`.
