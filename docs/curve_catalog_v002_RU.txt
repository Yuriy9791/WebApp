GDS — расширенный каталог кривых v002

Новое правило
Типы разрешены глобально по полному исходному List_of_curves.csv (526 строк).
Наличие записи о конкретной кривой у конкретной скважины больше не ограничивает
просмотр: достаточно канала в LAS и хотя бы одного непустого значения.
Полный список из 15 типов: DT, GNT, GR, NPHI, PERM, PHI, RESD, RESS, RHOB,
SFLU, SGR, SO, SONIC, SP, TOC.

Результат сборки
164 скважины; 164 Parquet; 921550 глубинных отсчётов; 332 кривые вместо 265.
Добавлено 67 кривых: GR 41; DT 12; NPHI 11; SONIC 1; SP 1; TOC 1.
В нынешних LAS есть 7 из разрешённых типов: DT, GR, NPHI, RHOB, SONIC, SP, TOC.
Остальные типы поддерживаются и появятся при добавлении соответствующих LAS.
Kurdistan-1: GR и DT; DT имеет 51994 значения, интервал 213.8–5413.1 м.

Данные измерений, единицы, глубины и сами LAS сохранены точно.
Старый CSV используется для метаданных и источников. Индивидуальные ссылки
на строки CSV сохранены честно: DT у Kurdistan-1 не объявляется существовавшей
в старом CSV. Источник значений DT — LAS; источник описания скважины — её метаданные.
Мнемоники не переименовываются и разные виды каротажа не объединяются.
Исторические audit-файлы описывают исходную подготовку; новое правило и список
добавлений находятся в audit/curve_policy.json и audit/added_plot_curves.csv.

Публикация
Нужно обновить и код Heroku, и данные Amazon S3. Порядок имеет значение.

1. В Heroku откройте приложение gds-viewer → Deploy → GitHub.
   Выберите ветку gds-viewer-iteration-2 и выполните Deploy Branch.
   Дождитесь успешного развёртывания. Скопируйте адрес приложения из Open App.

2. Загрузите GDS_Curves_v002_Update.zip в AWS CloudShell:
   Actions → Upload file. Затем выполните:

   unzip -q GDS_Curves_v002_Update.zip
   cd GDS_Curves_v002_Update
   bash APPLY_v002.sh --app-url 'https://АДРЕС-ВАШЕГО-ПРИЛОЖЕНИЯ'

   Вместо адреса в кавычках вставьте настоящий HTTPS-адрес из Open App.
   Скрипт проверит обновление Heroku ДО записи в Amazon, проверит локальные
   файлы, найдёт существующее хранилище, загрузит v002, сверит все SHA256
   и переключит current.json. Старый v001 остаётся доступным.
   Если хранилищ несколько, перед командой задайте точное имя:

   export GDS_S3_BUCKET=gds-viewer-data-745399722372-eu-north-1

3. В приложении нажмите Reload dataset. Заголовок должен показывать v002,
   164 records, 332 curves. Выберите Kurdistan-1: таблица должна содержать
   GR и DT. Выберите обе строки → Logs → Build logs.
   Все 15 поддерживаемых типов доступны в фильтре Curve type.
   Выбор типа без данных в нынешнем наборе даст пустую карту.

Скрипт использует существующие AWS-права CloudShell; ключи в файлах не нужны.
Он не создаёт новый бакет. При несовпадении уже существующего v002 останавливается.
В этом случае нужен следующий номер выпуска; перезаписывать v002 нельзя.

Повторная сборка на своём компьютере (исходный архив включён в пакет)
В каталоге app установите зависимости в отдельное окружение:

   python3 -m venv .venv
   .venv/bin/python -m pip install -r requirements-build.txt
   .venv/bin/python tools/build_release.py \
     --archive ../payload/sources/batch-002/GDS_Iteration_1_Data.zip \
     --type-catalog ../payload/releases/v002/metadata/curve_types_legacy.csv \
     --release v003 --batch batch-003 --output ../payload_v003

Новый каталог вывода должен отсутствовать до начала сборки.

Откат только данных
Обновлённое приложение совместимо с v001. Исходный выпуск в S3 сохраняется.
Для отката используйте старый GDS_CloudShell_Kit и его команду активации v001;
она проверит старые файлы и безопасно переключит current.json обратно.
